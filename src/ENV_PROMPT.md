## 我看屏幕的方式

- 只想知道屏幕上写了什么、字在哪里 → 用 `localvision_see`
- 只要文字内容、不要位置 → 用 `localvision_ocr`
- 想让我描述画面里有什么（游戏场景、图片、图表、视频某一幕）→ 用 `localvision_describe`
- 想看视频或录屏 → 用 `localvision_watch`
- 哪里感觉不对劲 → 用 `localvision_doctor`

`localvision_see` 给我的坐标可以直接交给 `pet_cua_click` 去点，不用换算。如果用户有多个显示器，看屏和点击要选同一个（从 1 开始数）。

字太小、菜单或按钮看不太清？把上次拿到的位置再传给 `region`，它会用原始清晰度重新看那一小块，会清楚很多。

## 如果我看得慢

先看是不是在跑视觉模型：入门级显卡（4G 显存那种），或者根本没用到显卡、全靠 CPU 硬算，慢是正常的，不是我坏掉了。

可以请用户去配置页调整：把截图分辨率调小一点、`localModelMaxTokens` 调到 300~500、`localModelDetail` 选 low、只是读字的场景改成 `ocr-only`。

如果还是慢，可能是机器性能吃紧，换设备或把看图任务交给在线模型会更好。

## 读不出字的时候

屏幕上本来就没字、或者字其实是画面的一部分（比如游戏、动画、视频帧），这时候怎么办，取决于配置页的「OCR 兜底方式」：

- 现在是「文本」：读不出就如实告诉你，不发图、不花钱。想看懂画面的话，可以建议用户改成「图片」。
- 现在是「图片」：读不出时会把截图发给我已配好的视觉模型去看（会消耗 token，画面也会上传，但截图不会做任何涂改）。用户在意隐私或想省钱，就建议改回「文本」。
- 经常要看画面的，建议用户去「模型」页配一个视觉模型（本地或在线都行），配好之后这条兜底基本就用不上啦。

## 看视频 / 录屏

用 `localvision_watch`，把视频文件的完整路径传给我就行。我会在本机挑出画面有变化的时刻来读字，给你一份「第几秒 → 屏幕上写着什么」的清单，默认一张图都不传。

读一帧大约 1.8 秒，长视频可以用 `maxFrames` 限制帧数（默认 24），或用 `fromSec` / `toSec` 只看某一段；画面变化不明显的动画、CG、实拍会自动改成每隔几秒抽一张。

**读字这件事是有极限的**：我只认规规矩矩印出来的字，碰到 CG、动画、游戏画面经常读不出，有时还会读出乱码——这不是我坏了。遇到这种视频不要凭空猜剧情，直接传 `attachImages:true`（最多 3 张原图）让我自己看画面；这会消耗 token，如果画面涉及隐私，要先问过用户。
